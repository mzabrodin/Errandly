# API-контракт фронтенду

Фронтенд звертається до `/api` (у dev — через проксі Vite). Поки бекенд у розробці, ці ендпоінти імітує MSW (`src/mocks/handlers.ts`), тому мок — це робоча специфікація: якщо реалізація на бекенді відрізняється, оновіть і моки, і цей файл.

Форми запитів і відповідей задають DTO бекенду: `backend/openapi.json` (Swagger UI: `/api/docs` у `npm run dev:backend`) → `src/shared/api/schema.d.ts` (`npm run api:sync`); `src/shared/api/types.ts` лише дає їм доменні назви. Цей файл описує поведінку: хто має доступ, які помилки й побічні ефекти. Бекенд уже приймає й валідує всі запити; ще не реалізовані ендпоінти (календар, сповіщення, статистика, вхід через Google) відповідають `501 NOT_IMPLEMENTED`.

Мова (`locale`) — `"uk"` (за замовчуванням) або `"en"`: нею працюють інтерфейс і листи; під час реєстрації фронтенд передає поточну мову інтерфейсу. Час — ISO 8601 в UTC. Автентифікація — cookie-сесія (`credentials: 'include'`).

## Помилки

Тіло помилки: `{ "code": "...", "fields"?: { "<поле>": "<код>" }, "retryAfterSeconds"?: number, "groups"?: string[] }` (схема `ApiErrorDto`, коди — `backend/src/common/errors/error-codes.ts`).

| Статус | Коди                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------- |
| 400    | `VALIDATION` (з `fields`), `TOKEN_INVALID`, `WRONG_PASSWORD`                                                |
| 401    | `UNAUTHENTICATED`, `INVALID_CREDENTIALS`                                                                    |
| 403    | `FORBIDDEN` (не учасник групи; запит з чужого `Origin`), `ADMIN_ONLY`, `NOT_ASSIGNEE`, `EMAIL_NOT_VERIFIED` |
| 404    | `NOT_FOUND` (зокрема id не у форматі UUID і невідомий маршрут)                                              |
| 409    | `EMAIL_TAKEN`, `LAST_ADMIN`, `TASK_DONE`, `UNDO_EXPIRED`, `CANNOT_REMOVE_SELF`, `CALENDAR_NOT_CONNECTED`    |
| 410    | `INVITE_INVALID`                                                                                            |
| 413    | `FILE_TOO_LARGE` (аватарка > 512 КБ)                                                                        |
| 423    | `ACCOUNT_LOCKED` (+ `retryAfterSeconds`)                                                                    |
| 429    | `TOO_MANY_REQUESTS` (ліміт запитів з одного IP; заголовок `Retry-After`)                                    |
| 500    | `INTERNAL` (деталі лише в логах сервера за `X-Request-Id`)                                                  |
| 501    | `NOT_IMPLEMENTED` (контракт є, логіки ще немає)                                                             |

Коди полів у `fields`: `required`, `tooLong`, `invalid`, `weak` (пароль), `inPast` (термін), `range` (складність 1–5), `noWeekdays`, `beforeFrom` (кінець відсутності раніше за початок), `type` (неправильний тип значення або файлу), `unknown` (поле, якого немає в контракті). Для кожного поля — один код, найважливіший.

## Автентифікація

| Метод | Шлях                        | Тіло → відповідь                                  | FR    |
| ----- | --------------------------- | ------------------------------------------------- | ----- |
| GET   | `/auth/me`                  | → `User` або 401                                  | —     |
| POST  | `/auth/register`            | `{ name, email, password, locale? }` → 201 `User` | 01–04 |
| POST  | `/auth/login`               | `{ email, password }` → `User`                    | 05–06 |
| POST  | `/auth/logout`              | → 204                                             | 09    |
| GET   | `/auth/google?next=`        | редирект на OAuth Google, потім на `next`         | 07    |
| POST  | `/auth/forgot-password`     | `{ email }` → 204 (завжди)                        | 08    |
| POST  | `/auth/reset-password`      | `{ token, password }` → 204                       | 08    |
| POST  | `/auth/verify-email`        | `{ token }` → `User`                              | 04    |
| POST  | `/auth/verify-email/resend` | → 204                                             | 04    |

Посилання в листах фронтенд очікує такі: `/verify-email/:token`, `/reset-password/:token`, `/invite/:token`.

Поведінка (реалізовано на бекенді):

- **Сесія** — HttpOnly-cookie `errandly_session` (`SameSite=Lax`, `Path=/api`, `Secure` у production). Вона діє 30 днів від останнього використання й продовжується сама. Реєстрація та вхід її встановлюють, вихід і видалення акаунта — прибирають. Усі маршрути, крім позначених як публічні (реєстрація, вхід, вихід, відновлення пароля, підтвердження email, `GET /invites/:token`, `/health`), без сесії відповідають `401 UNAUTHENTICATED`.
- **Вхід**: невідомий email і хибний пароль відповідають однаково (`401 INVALID_CREDENTIALS`). П'ята невдала спроба поспіль блокує акаунт на 15 хвилин (`423 ACCOUNT_LOCKED`, `retryAfterSeconds: 900`), і поки блокування діє, навіть правильний пароль отримує 423.
- **Листи** надсилаються після коміту з повторами (30 с, 2 хв, 8 хв, 32 хв). Збій пошти не скасовує реєстрацію. Кожен лист містить новий токен, а попередні посилання того ж типу перестають діяти.
- **Посилання**: підтвердження email діє 48 годин, відновлення пароля — 1 годину. Обидва одноразові.
- **Відновлення пароля** знімає блокування й завершує всі сесії. `POST /me/password` завершує всі сесії, крім поточної. `verify-email/resend` нічого не робить, якщо email уже підтверджено.
- **Порядок перевірок**: спершу валідується тіло, тому слабкий пароль дає `VALIDATION` раніше, ніж `TOKEN_INVALID` чи `WRONG_PASSWORD`.
- **Ліміти**: 10 запитів на хвилину з IP до реєстрації, входу, відновлення пароля й листів, 100 — до решти API (`429 TOO_MANY_REQUESTS`).
- `GET /auth/google` поки відповідає `501`.

## Групи

| Метод  | Шлях                              | Тіло → відповідь                                                                                 | FR    |
| ------ | --------------------------------- | ------------------------------------------------------------------------------------------------ | ----- |
| GET    | `/groups`                         | → `GroupSummary[]`                                                                               | 18    |
| POST   | `/groups`                         | `{ name }` → 201 `Group`; 403 `EMAIL_NOT_VERIFIED`                                               | 10    |
| GET    | `/groups/:id`                     | → `Group` (з учасниками та їхніми відсутностями)                                                 | 40    |
| POST   | `/groups/:id/invites`             | `{ email? }` → 201 `{ url, expiresAt }` (адмін)                                                  | 11    |
| GET    | `/invites/:token`                 | → `InviteInfo` або 410 (публічний)                                                               | 12–14 |
| POST   | `/invites/:token/accept`          | → `{ groupId }`; 403 `EMAIL_NOT_VERIFIED`                                                        | 12    |
| DELETE | `/groups/:id/members/:userId`     | → 204, перерозподіл задач (адмін)                                                                | 15    |
| PATCH  | `/groups/:id/members/:userId`     | `{ role: "admin" \| "member" }` → 204; 409 `LAST_ADMIN`, якщо знімають останнього адміна (адмін) | 16    |
| POST   | `/groups/:id/leave`               | → 204 або 409 `LAST_ADMIN`                                                                       | 16    |
| POST   | `/groups/:id/absences`            | `{ from, to }` (yyyy-mm-dd) → 201 без тіла; `to` раніше за `from` — `beforeFrom`                 | 17    |
| DELETE | `/groups/:id/absences/:absenceId` | → 204; 404 `NOT_FOUND`, якщо відсутності немає або вона чужа                                     | 17    |

Поведінка (реалізовано на бекенді):

- **Доступ** (NFR-SEC-04): не учасник отримує `403 FORBIDDEN` без даних, і для неіснуючої групи теж, тож відповідь не видає, чи група існує. Учасник на діях адміністратора отримує `403 ADMIN_ONLY`.
- **Запрошення** діє 7 днів і будь-яку кількість разів. Прострочене чи відкликане дає `410 INVITE_INVALID`. Повторне прийняття учасником нічого не змінює.
- **Запрошення з `email`**: адміністратор отримує своє посилання, а одержувач — окреме, у листі. Лист іде після коміту з повторами, мовою акаунта одержувача, а якщо акаунта немає — мовою адміністратора. Новий лист на ту саму адресу відкликає попереднє надіслане посилання.
- **Учасники**: прибрати учасника, якого немає в групі, — `404 NOT_FOUND`; прибрати себе — `409 CANNOT_REMOVE_SELF`. Колір новачка — перший вільний у групі.
- **Вихід**: коли групу залишає останній учасник, вона видаляється разом із задачами й запрошеннями.
- **Видалення акаунта** блокується (`409 LAST_ADMIN` + `groups`), поки користувач — єдиний адміністратор групи, де є інші учасники. Інакше користувач виходить з усіх груп у тій самій транзакції.

## Задачі

| Метод  | Шлях                                    | Тіло → відповідь                                                  | FR           |
| ------ | --------------------------------------- | ----------------------------------------------------------------- | ------------ |
| GET    | `/groups/:id/tasks?from=&to=&seriesId=` | → `Task[]` за `dueAt` у `[from, to)`; усі параметри необов'язкові | 23           |
| GET    | `/tasks/:id`                            | → `Task` (403 для не-учасника, 404 якщо видалено)                 | 23, 40       |
| POST   | `/groups/:id/tasks`                     | `TaskInput` → 201 `Task` (перший екземпляр; адмін)                | 19–21, 27–30 |
| PATCH  | `/tasks/:id?scope=one\|series`          | `TaskInput` → `Task` (адмін)                                      | 22, 30       |
| DELETE | `/tasks/:id?scope=one\|series`          | → 204 (адмін)                                                     | 22           |
| POST   | `/tasks/:id/complete`                   | → `Task` (лише виконавець)                                        | 24           |
| DELETE | `/tasks/:id/complete`                   | → `Task`; виконавець — протягом 24 год, адміністратор — будь-коли | 24           |
| PATCH  | `/tasks/:id/assignee`                   | `{ assigneeId }` → `Task` (адмін)                                 | 30–31        |

`TaskInput.assigneeId = null` означає автоматичний розподіл. `status` обчислює сервер: `done` → `overdue` (термін минув) → `unassigned` → `planned`.

Поведінка (реалізовано на бекенді):

- **Доступ**: задачі бачать лише учасники групи (`403 FORBIDDEN` без даних). `/tasks/:id` спершу відповідає `404 NOT_FOUND`, якщо задачі немає, а вже потім `403`. Створювати, редагувати, видаляти й призначати вручну може лише адміністратор (`403 ADMIN_ONLY`).
- **Створення**: серія розгортається на 4 тижні вперед, щогодини доповнюється до цього горизонту й одразу отримує виконавців. Відповідь — перший екземпляр. Ручний виконавець має бути учасником групи (`400`, `fields.assigneeId: 'invalid'`) і стає виконавцем кожного нового екземпляра серії.
- **Часовий пояс**: серія бере пояс адміністратора, який її створив (`User.timezone`). «Щочетверга о 20:00» лишається 20:00 за його годинником і після переходу на зимовий час, а відсутності порівнюються з днем терміну в цьому поясі. Щомісячна задача з 29–31 числа в коротших місяцях припадає на останній день.
- **Розподіл** (FR-27–29): з учасників, які не відсутні в день терміну, — той, у кого найменша сума складності задач із терміном за 4 тижні до цього; за рівності — хто найдовше не виконував саме цю серію, далі за ім'ям. Нікого немає — задача без виконавця (`unassigned`).
- **Редагування**: `scope=one` змінює лише цей екземпляр; `inPast` перевіряється, тільки якщо змінили `dueAt`. `scope=series` для повторюваної задачі перебудовує серію з нового `dueAt`: майбутні невиконані екземпляри створюються наново (з новими `id`), виконані й минулі лишаються. Для одноразової задачі `series` діє як `one`.
- **Видалення**: `scope=series` видаляє невиконані екземпляри, а виконані залишає в історії; така серія більше не поповнюється.
- **Виконання**: позначити може лише виконавець (`403 NOT_ASSIGNEE`), повторне позначення нічого не змінює. Скасувати — виконавець протягом 24 годин (`409 UNDO_EXPIRED`), адміністратор будь-коли.
- **Ручне призначення**: не для виконаної задачі (`409 TASK_DONE`); виконавець має бути учасником (`400`). Автоматичний розподіл його вже не змінює.
- **Перерозподіл**: коли учасник виходить чи його видаляють, усі його відкриті задачі (і ручні) отримують нових виконавців, а його серії переходять на автоматичний розподіл. Нова відсутність переносить лише автоматично розподілені задачі на ці дні.

## Профіль і акаунт

| Метод  | Шлях                | Тіло → відповідь                                                                                | Вимоги                  |
| ------ | ------------------- | ----------------------------------------------------------------------------------------------- | ----------------------- |
| PATCH  | `/me`               | `{ name?, timezone?, locale? }` → `User`                                                        | NFR-COMP-03, NFR-USE-03 |
| POST   | `/me/avatar`        | `multipart/form-data`, поле `file` (JPEG, PNG, WebP чи GIF ≤ 512 КБ) → `User` з `avatarUrl`     | —                       |
| DELETE | `/me/avatar`        | → `User` (`avatarUrl` — фото від Google або `null`)                                             | —                       |
| POST   | `/me/password`      | `{ currentPassword, newPassword }` → 204; 400 `WRONG_PASSWORD`                                  | FR-01 (правила пароля)  |
| DELETE | `/me`               | → 204; 409 `LAST_ADMIN` + `groups: string[]`, якщо користувач — єдиний адмін групи з учасниками | NFR-LEG-02              |
| POST   | `/me/calendar/sync` | → `CalendarStatus` (оновлює `lastSyncedAt`); 409 `CALENDAR_NOT_CONNECTED`                       | FR-35                   |

Аватарки (реалізовано на бекенді):

- **Яке фото показується** (`avatarUrl` у `User` і в учасниках групи): завантажене користувачем, інакше фото з Google-акаунта (після входу через Google), інакше `null`, і фронтенд показує ініціали. Видалення свого фото повертає фото з Google.
- **Завантаження**: формат визначається за вмістом файлу, а не за назвою. SVG, TIFF і решта — `400 VALIDATION` (`fields.file: 'type'`), файл без поля — `fields.file: 'required'`, більше за 512 КБ або понад 40 Мп — `413 FILE_TOO_LARGE`. Бекенд перекодовує фото у WebP 256×256 без метаданих (EXIF, GPS не зберігаються, NFR-LEG-01).
- **Файл** лежить в об'єктному сховищі (S3-сумісне, у compose — SeaweedFS), не в базі. Його віддає `GET /api/avatars/<uuid>.webp` без сесії: ключ випадковий, і бачать його лише учасники спільних груп. Кожне завантаження дає новий ключ, тож браузер кешує фото назавжди (`Cache-Control: immutable`). Цей маршрут не входить в OpenAPI: його читає `<img>`, а не клієнт API.
- **Старий файл** видаляється після коміту (подія `user.avatarDiscarded`, з повторами): під час заміни, видалення фото й видалення акаунта (NFR-LEG-02). Якщо сховище недоступне, завантаження відповідає `500`, а попереднє фото лишається.

## Сповіщення в сервісі

| Метод | Шлях                  | Тіло → відповідь                                              |
| ----- | --------------------- | ------------------------------------------------------------- |
| GET   | `/notifications`      | → `{ items: AppNotification[], unread: number }` (останні 50) |
| POST  | `/notifications/read` | `{ ids?: string[] }` → 204; без `ids` — позначити всі         |

Типи подій (`AppNotification.type`): `groupCreated`, `groupJoined`, `memberJoined` (адмінам), `taskAssigned`, `taskUnassigned` (попередньому виконавцю), `taskOverdue` (від фонового процесу FR-25), `roleGranted`, `roleRevoked`, `removedFromGroup`. Сповіщення не створюється, якщо дію виконав сам отримувач. Фронтенд опитує список раз на 30 с.

## Листи

Шаблони й відправка — `backend/src/mail` (`MailService.send(template, to, data, locale)`). Лист іде мовою акаунта одержувача (`User.locale`); запрошення людині без акаунта — мовою того, хто запрошує. Шаблони: `verifyEmail`, `resetPassword`, `invite`, `taskAssigned`, `taskDueSoon`, `taskOverdue`; поля даних описані в `backend/src/mail/templates/index.ts`. Посилання в листах фронтенд очікує на `/verify-email/:token`, `/reset-password/:token`, `/invite/:token`, `/g/:groupId/tasks/:taskId`, `/settings`.
