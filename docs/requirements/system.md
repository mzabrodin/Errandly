# Системні вимоги

Джерело: звіт `docs/Errandly.pdf`, практична робота №4 (с. 30–35). Функціональні вимоги — у [functional.md](functional.md), нефункціональні — у [non-functional.md](non-functional.md).

Мета — визначити системні вимоги до Errandly на основі концепції проєкту з ПР1, функціональних вимог ПР2 та нефункціональних вимог ПР3. Системні вимоги деталізують функції та обмеження системи: її середовище, взаємодію компонентів, зберігання даних та інтеграції.

До складу Errandly входять веб-інтерфейс, серверна бізнес-логіка, база даних і фонові процеси. Зовнішні залежності – браузер, мережа, Google Calendar, авторизація Google та Gmail SMTP. GitHub і GitHub Actions забезпечують розробку й доставку. Нативний мобільний застосунок, Outlook, Apple Calendar, облік витрат і чат у цю версію не входять.

SYS – системна вимога; FR і NFR – посилання на вимоги попередніх робіт. Пріоритети: M – Must have, S – Should have. Вимоги ПР2–ПР3 залишаються чинними; наведені нижче формулювання їх доповнюють.

Для SYS-24 обрано 128 випадкових бітів, тобто 16 випадкових байтів, за аналогією з рекомендацією OWASP щодо генерації власних ідентифікаторів сесій.

Сформовано 28 вимог: 21 Must have та 7 Should have. Обов'язкові умови безпеки й цілісності застосовуються до опційної функції, якщо її реалізовано; вони не змінюють її початковий пріоритет.

## Перевірка виконання вимог

Середовище перевіряється запуском за README; доступ, дані та інтеграції – API й інтеграційними тестами; швидкодія – навантажувальним тестом; відновлення – перезапуском і пробним відновленням БД. План перевірки:

| Сценарій          | Передумова та дія                                                                                             | Очікуваний результат                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| AC-01 (SYS-07)    | Автентифікований користувач поза групою запитує її задачі через API.                                          | HTTP 403; даних групи немає; БД не змінено.                                                                        |
| AC-02 (SYS-09)    | Доступні Аня з навантаженням 6 і Богдан з 3. Створено задачу складністю 2.                                    | Задачу призначено Богдану; його навантаження стало 5 за тією самою обліковою вибіркою.                             |
| AC-03 (SYS-19–20) | Calendar API недоступний; термін задачі змінено; сервер перезапущено. API відновлено в межах повторних спроб. | Термін збережено; операцію не втрачено; оновлено одну відповідну подію. Дублікатів немає, сторонні події незмінні. |
